# L.Q记工本 2.2.1

简体中文 | [English](README.en.md)

> 简明安装与使用说明见 [项目介绍与使用指南](项目介绍与使用指南.md)。

L.Q记工本是一款完全离线的 Windows 工人出勤与工资记录工具。安装版自带运行环境，无需联网、账号或另装 Node.js；数据只写入本机。2.2.1 继承 2.2.0 的请假、工地成本统计、JSON 迁移、Excel、打印和 PDF 等能力，并修复桌面版偶发无法继续键盘编辑的问题。

## 2.2.1 修复

- 关闭前若首笔月度保存返回“结果未知”，日薪、加班倍率和备注等后续草稿不再永久等待；程序会保留原操作 ID 与顺序完成一次安全核对重试。
- 在“保存尚未完成”对话框选择“取消关闭”后，页面会立即退出关闭锁定并恢复编辑；重试关闭产生了新请求 ID 时也不会把旧页面留在禁用状态。
- 日薪、加班倍率、备注等编辑框显示明确的文本光标和插入符；真正只读或关闭锁定时则显示清晰的禁用样式，避免看似可编辑却没有“|”提示。
- 首次打开和再次双击已运行程序时会同时恢复窗口与页面键盘焦点；归档当前工人后自动切换到仍在使用的工人，避免停留在只读历史页。

## 2.2.0 功能

- 高频记工：支持单格、路径刷选、矩形区域圈选（全勤 / 全休 / 卖命）、右键或 `Backspace` 清空、“本周全勤”和最多 50 步统一撤销。方向键移动后，数字键及清空键会作用于最新键盘焦点；只有真实移动鼠标后才切回鼠标停留格，避免操作又跳回原格。
- 逐时段请假：上午、下午和加班可分别设置带薪或无薪；加班带薪另选半工或一工。请假格使用斜纹和“假”标识，并锁住普通点击、数字键、`Backspace`、路径刷选、批量记工和工地修改；必须通过“调整请假 / 取消请假”显式变更。带薪请假进入工资但不计实际工数、人数或人次，无薪请假金额为零。
- 键盘与月份：`←` / `→` 在同一时段切换日期，`↑` / `↓` 沿视觉列移动并可跨周；`Ctrl+←` / `Ctrl+→` 切月。Windows 安装版可用 `Ctrl+T` 回到今天，所有运行方式均可用 `Alt+T`。
- 工人与搜索：侧栏支持姓名多关键词过滤和 `Ctrl+↑` / `Ctrl+↓` 切换；搜索输入只保留一个清空按钮。桌面和窄屏界面均提供已归档工人入口，归档人员可以只读查看或恢复。
- 工地统计：新增月度 / 年度“工地统计”页，可查看人数、人次、上午/下午/加班工数、请假、基础工资、补贴、扣款和净成本，并下钻到工人明细。基础工资按每个实际出勤时段归入工地；没有工地的出勤进入“未分配出勤”，补贴扣款可选工地，未选时进入“未归属调整”。请假单列，不虚增出勤人数、人次或工数。
- 日薪历史：工人编辑页按生效月份展示“月度日薪变化”。默认日薪只作为没有历史月记录时的基线；某月日薪会从该月起沿用，直到下一次月度调整。
- 工资口径：出勤、带薪请假、加班倍率、补贴扣款与工地成本共同使用一份按分对账的工资明细账，避免汇总、工资条和导出之间出现舍入差异。月表、工资条、工地统计、打印/PDF 与 Excel 使用相同结果。
- 保存与撤销：普通请求默认 10 秒超时，大型备份请求为 60 秒；写请求携带持久化操作 ID，超时或断线后的同一任务可安全重试而不会重复入账。只有服务端确认成功的操作进入撤销栈，考勤撤销也使用前后快照冲突校验，不会静默覆盖撤销点之后的新修改。
- 增量响应：常规写操作返回本次数据增量，并在客户端按 revision 合并；备份恢复等大型流程仍可返回完整状态。数据量增长后不再让每个单格保存都传回整本记录。
- 数据与备份：健康检查只读取内存元数据；完整备份校验留到预览或恢复。每日备份和恢复前备份分别保留最近 30 份和 10 份，互不挤占；每周外部备份仍保留最近 12 份。设置页会显示最近一次自动周备份失败时间，并针对磁盘已满、权限和 I/O 错误给出稳定提示。
- 桌面导出：JSON、Excel 和 PDF 均先在目标目录写临时文件并同步到磁盘，再原子替换最终文件；取消选择不会创建文件，失败会清理临时文件。XLSX 保存桥接正确接收渲染进程的 `Uint8Array`。
- 桌面关闭与假死：关闭前以唯一请求 ID 等待草稿和保存队列，最长 25 秒并确认响应，能够区分迟到或过期答复。窗口无响应时重复事件会合并，默认继续等待且不会自动重载；只有用户明确选择时才强制退出。
- 桌面边界：桌面 API 使用每次启动随机生成的会话密钥，IPC 只接受当前主窗口和本机页面；服务端同时使用数据目录指纹与进程锁阻止两个实例静默共用同一目录。磁盘满、只读文件系统和 I/O 故障会返回可操作的错误信息。
- 既有能力：继续支持未来日期会话确认、失败格提示、批量添加、图片/Emoji 头像、当日工地总览、发薪结清、年度十二月图表、内部备份预览恢复、浅色/深色主题、窄屏布局和打印专用样式。

## 键盘快捷键

| 快捷键 | 作用 |
| --- | --- |
| `Ctrl+N` | 添加工人 |
| `Ctrl+F` | 打开全局搜索 |
| `Ctrl+Z` | 撤销最近一次支持的操作，最多 50 步 |
| `Ctrl+T` | 回到今天（仅 Windows 安装版，浏览器会保留“新建标签页”） |
| `Alt+T` | 回到今天（Windows 安装版和浏览器均可用） |
| `Ctrl+←` / `Ctrl+→` | 切换上月 / 下月 |
| `Ctrl+↑` / `Ctrl+↓` | 按侧栏当前可见顺序循环切换工人 |
| `←` / `→` | 同一时段切换相邻日期 |
| `↑` / `↓` | 沿考勤表同列上下移动，可跨周 |
| `1` / `2` | 上午、下午直接标记出工 / 未出工 |
| `3` / `4` | 加班直接标记半工 / 一工 |
| `Backspace` | 清空鼠标停留格或键盘聚焦格；请假格除外 |

输入框、选择框和弹窗中保留系统原有键盘操作。

## 数据安全、备份与兼容

安装版正式数据位于 `%APPDATA%\L.Q记工本\data`：

- `records.json`：正式数据；
- `records.last-good.json`：最近有效副本；
- `backups`：程序内部的每日备份及恢复前备份。

每次修改均经过串行队列、完整校验和原子写入，单份应用数据上限为 64 MiB；接近上限时健康状态会提前提示。恢复 JSON 时先执行无副作用检查，再自动保存恢复前数据。2.2.1 继续使用数据 schema v8，支持 v1 → v2 → v3 → v4 → v5 → v6 → v7 → v8 链式迁移；未知未来版本会被拒绝，旧数据在首次真实修改时才按现有原子流程落盘。v1–v6 的历史月份倍率仍统一迁移为 1 倍，v1–v7 不会凭空生成请假或工地归属，因此旧工资不变。

schema v8 新增：

- `AttendanceEntry.morningLeave / afternoonLeave / overtimeLeave`：逐时段保存带薪或无薪请假；加班带薪同时保存半工或一工单位；
- `PayAdjustment.siteId`：补贴扣款可选工地，`null` 表示未归属；
- `operationReceipts`：服务端内部保存有界的操作回执，用于识别同一写请求重试，不作为界面业务记录。

Windows 桌面版默认开启每周外部备份。应用启动时及运行期间检查，距离上次成功备份达到 7 天时，将完整 JSON 原子写入 Windows“文档\L.Q记工本备份”，仅保留最近 12 份本程序固定前缀的周备份。设置页可关闭此功能、立即备份或打开目录；只有写入成功后才更新时间，成功后会清除先前的自动备份失败状态。程序关闭期间不会驻留后台。浏览器启动方式不能写入固定 Windows 文档目录，请继续使用“导出备份”手动保存。

工人和被历史考勤引用的工地只归档，不永久删除。安装、升级和正常卸载不会主动删除独立的数据目录。跨电脑迁移请使用“导出备份 / 从 JSON 恢复”，不要复制 `out`、`release` 或安装目录。详见[旧数据迁移说明](docs/旧数据迁移.md)和[2.1 升级与验收说明](docs/2.1-upgrade.md)。

## 使用提示

1. 在侧栏添加单名工人，或进入“批量添加”一次录入一批姓名与日薪。
2. 点击或拖动考勤格记工；也可使用方向键、数字键与 `Backspace`。需要请假时点击格内“假”，或圈选范围后进入“请假”。
3. 点击日期打开“当日详情”，填写每日备注、调整请假或覆盖三个时段的实际工地。
4. 在“当日总览”按工地查看当天人员，在“工地统计”核对月度/年度成本，在“年度汇总”查看结清情况和十二月图表。
5. 桌面版定期检查“文档\L.Q记工本备份”；跨电脑前仍建议手动导出完整 JSON。

应用只允许一个实例运行；再次启动会激活已打开窗口。关闭时会先刷新本月日薪、加班倍率、月备注和尚未完成的保存操作。

## 重新打包 2.2.1

正式发布前，先确认 `package.json` 与 `package-lock.json` 的项目版本已统一为 `2.2.1`。源码验收完成后，在项目根目录 PowerShell 中执行：

```powershell
npm ci
npm test
npm run typecheck
npm run test:launcher
npm run build
npm run test:e2e
npm run desktop:make

$version = (Get-Content -Raw -LiteralPath '.\package.json' | ConvertFrom-Json).version
if ($version -ne '2.2.1') { throw "待发布版本应为 2.2.1，当前为 $version" }
$exe = ".\release\L.Q记工本-$version-Setup.exe"
$actual = (Get-FileHash -Algorithm SHA256 -LiteralPath $exe).Hash.ToLowerInvariant()
$recorded = ((Get-Content -LiteralPath "$exe.sha256") -split '\s+')[0].ToLowerInvariant()
[pscustomobject]@{
  Actual = $actual
  Recorded = $recorded
  Match = ($actual -eq $recorded)
}
```

`desktop:make` 现在本身就是完整发布门禁，顺序为：

1. `desktop:make:raw` 构建前端、生成图标，并通过 Electron Forge/Squirrel 生成 `package.json` 当前版本的 ASAR 与安装包；
2. `release:verify` 比对源码与 ASAR 的版本、运行文件清单和指纹，并执行严格运行时白名单与用户数据排除检查；
3. `test:desktop-smoke` 使用隔离的数据和 Windows 文档目录启动刚生成的桌面程序，验证运行、关闭握手及桌面桥接，并为同一份产物记录门禁；
4. `release:finalize` 再次核对产物身份和两份未过期门禁，只有全部匹配才把当前版本安装包与 `.sha256` 整理到 `release`。

ASAR 运行白名单只包含 `package.json`、`desktop/**`、`dist/**`、服务端运行文件、顶层 `shared/*.mjs` 和 `electron-squirrel-startup`；`shared/*.d.mts`、源码、测试、缓存及真实数据继续排除。发布指纹门禁使用相同边界，缺少共享运行模块或混入额外文件都会停止发布。

因此，单独运行 `desktop:make:raw`、看到 Forge 成功或对旧 ASAR 运行 smoke 都不代表发布完成。中文项目路径继续由包装脚本临时映射到 ASCII 盘符，并使用 ASCII 临时目录。发布整理使用带版本号的新文件名，不会删除 `release` 中既有的 2.2.0 和 2.1.1 安装包；在 2.2.1 干净机升级和数据保留验收完成前，应继续保留 2.2.0 EXE 及其校验文件作为可核对的旧产物。

发布前仍需在未安装 Node.js 的干净 Windows 10/11 x64 电脑上验证：2.2.1 首次安装、2.2.0 → 2.2.1 覆盖升级、schema v8 数据保留、JSON/Excel/PDF 保存、内部/每周备份、窗口关闭与取消后继续编辑，以及卸载后数据保留。不要在这些实机项目尚未执行时把它们记录为已通过。

## 开发运行

浏览器版本机服务：

```powershell
npm run build
npm start
```

前端开发可运行 `npm run dev`；生产服务由 `server/index.mjs` 提供构建后的 `dist` 和本机数据接口。
