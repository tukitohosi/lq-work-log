# L.Q记工本 2.1 升级与验收说明

本文面向维护者，概括 2.1.1 的数据边界、代码模块和发布验收。具体使用方式见项目根目录的 `README.md`。

## 兼容边界

- 应用继续完全离线运行，不新增账号、云端同步或网络依赖。
- 正式数据目录保持 `%APPDATA%\L.Q记工本\data`，应用标识和安装包命名规则不变。
- schema 从 v6 升级到 v7，新增 `Settings.defaultOvertimePayPercent` 和 `MonthlyRecord.overtimePayPercent`；两者以整数百分比保存，范围为 `0..1000`。
- v1–v6 先经过既有迁移链再补 v7 默认值 `100`；导出和恢复需要完整保留 v7 字段，历史工资保持 1 倍不变。
- 结清仅是带服务端时间的状态标记，不锁定月度记录，也不因后续金额变化自动取消。
- 未来日期已有记录照常保留。未来格仅以透明度区分，不在格内显示“未来”文字、标签或角标；写入许可只在用户本次会话确认后生效。

## 核心交互验收

1. 在月表上不点击格子，只悬停一个有效格；数字键与 `Delete` 应直接作用于该格。点击聚焦另一格后再悬停新格，编辑快捷键应跟随新悬停格，方向键仍从聚焦格移动。
2. `↓` 应按上午 → 下午 → 加班 → 下周同列上午移动；`↑` 反向移动。月首、月末空白位置没有目标时停止。
3. 上午/下午仅响应数字 `1`、`2`，加班仅响应 `3`、`4`；`Delete` 清空状态和对应工地，空白格不发送写请求。输入控件、弹窗和归档月表均隔离这些快捷键。
4. 未来格只降低透明度。首次单格、快捷键、拖拽、区域、本周全勤、工地或日备注写入未来日期时均进入同一确认；取消后不得出现部分乐观写入。
5. 模拟保存失败时，对应格或日期出现红色角标；重试成功或被新成功写入覆盖后消失。
6. 连续输入本月日薪、加班倍率或月备注，在 500 ms 后分别合并保存；失焦、切换工人/月、恢复和关闭时立即 flush，且不得把旧上下文内容写入新上下文。
7. 批量添加先校验全部非空行，再逐行保存；中途失败应报告成功人数并保留剩余行。重名只提醒，不阻止提交。
8. 头像选择区聚焦后可粘贴图片；Emoji 只接受一个可见字符，图片与 Emoji 互斥。
9. `Ctrl+F` 能找到并跳转工人、人员备注、单日备注、月备注、补贴/扣款项目与备注；归档工人只读打开。
10. 当日工地卡片按三个时段的实际工地分组，同一工人跨工地可进入多个组，但单组人数不得重复计算。
11. 结清状态与实际加班倍率显示在工资条、打印/PDF、月度及年度 Excel；年度筛选与 SVG 工数/工资图表使用当前筛选结果，tooltip 同显工数与实发。
12. 区域“全休”清空加班及加班工地，纯加班选区可执行；“全勤”仍不改加班。
13. 工人过滤支持规范化多关键词；`Ctrl+↑` / `Ctrl+↓` 只在当前匹配列表中循环且不包含归档工人。
14. 统一撤销按实际成功顺序覆盖考勤、单日/月备注、月日薪、月倍率与工资明细；删除明细恢复原 ID/时间戳，首次月记录可恢复为不存在，冲突必须整笔失败。
15. 设置页和数据损坏保护页都能列出、预览并恢复内部备份；响应与请求不得含绝对路径，恢复后撤销栈清空。

## 数据与性能验收

- 以同一份数据分别使用索引和兼容的非索引调用，考勤、月工资、年度汇总、工资条及 Excel 结果应完全一致。
- 使用多工人全年夹具覆盖考勤、月记录、补贴扣款、历史日薪、归档人员、跨工地和负工资，不以固定耗时数字作为跨机器门禁。
- v1 至 v7 迁移、v6 导入后按 1 倍计算、v7 导出再恢复、未知未来 schema 拒绝，以及已有未来记录保留均应有自动化覆盖。
- 1 倍工资须与旧算法逐分一致；1.5 倍、半工与奇数分日薪只改变工资，工数和工地统计不变，并且只做一次最终取整。
- 撤销栈覆盖混合 50 步、反向区域、取消路径、月边界、月记录存在性、补贴同 ID 恢复和冲突原子失败；失败任务覆盖精确格生命周期和重试。

## 内部备份验收

- 列表仅返回服务端生成的不透明 ID、类型、时间、大小、schema/revision 和数据统计，不返回路径或完整数据。
- inspect 拒绝路径穿越、失效 ID 与损坏 JSON；确认恢复继续走既有 `/api/restore` 并先生成恢复前备份。
- 数据损坏只读状态仍可列出、预览和恢复有效内部备份。
- 内部清理只匹配程序生成的 `daily-*`、`pre-restore-*`，不得删除 `pre-upgrade-*` 或其他人工文件。

## 每周备份验收

- 默认开启；启动时和运行中检查，距离上次成功时间达到 7 天时补做，关闭期间不驻留。
- 固定写入 Windows“文档\L.Q记工本备份”，采用原子写入；成功后才更新 `lastWeeklyBackupAt`。
- 仅清理固定 `L.Q记工本每周备份-` 前缀的旧文件，保留最近 12 份，不影响目录内其他文件。
- 不可写目录应返回错误并保留原成功时间；“立即备份”和“打开备份目录”均通过受限桌面桥接。
- 桌面 smoke 必须设置隔离的数据和文档目录；浏览器 E2E 的 JSON、截图与 PDF 写入临时目录。

## 发布门禁

常规验收：

```powershell
npm ci
npm test
npm run typecheck
npm run test:launcher
npm run build
npm run test:e2e
npm run desktop:make
```

`npm run desktop:make` 按以下固定顺序执行：

```text
desktop:make:raw
  → release:verify
  → test:desktop-smoke
  → release:finalize
```

- `desktop:make:raw` 只生成当前安装候选，不整理 `release`。
- `release:verify` 校验源码与 ASAR 版本、逐文件指纹、严格运行时白名单和用户数据排除，并记录候选产物身份。
- `test:desktop-smoke` 必须启动同一候选产物，以隔离目录验证运行文件、桌面桥接、首次渲染崩溃恢复、本机服务、每周备份和关闭 flush，再记录 smoke 门禁。
- `release:finalize` 重新计算身份；任何源码、ASAR、主程序或安装包变化都会使旧门禁失效。只有两道门禁均匹配，才生成 `release\L.Q记工本-2.1.1-Setup.exe` 和对应 `.sha256`。

不要用历史 `out` 中的 ASAR 或单独一次 smoke 代替上述完整链。最终 SHA-256 以本次生成的 `.sha256` 文件为准，不在文档中写死。

## 发布前人工检查

在无 Node.js 的干净 Windows 10/11 x64 机器上完成并记录：

- 2.1.1 首次安装与启动；
- 从 2.1.0 覆盖升级；
- schema v6 JSON 恢复与 v7 再导出；
- 键盘、未来日期确认、批量添加、搜索、头像和结清流程；
- Excel、打印/PDF 和外部周备份；
- 正常卸载后 `%APPDATA%\L.Q记工本\data` 保留。

自动化通过不等于这些干净机项目已经完成；发布记录应明确区分自动化结果与实机结果。
